# i18n — Multilingual (en / he / ru / et) with RTL and locale routing

## Architecture

- **Locale primitives:** `src/lib/locales.ts` — **imports nothing**: `LOCALES`, `AppLocale`, `DEFAULT_LOCALE` (`en`), `LOCALE_COOKIE_NAME`, `LOCALE_COOKIE_MAX_AGE`, the RTL set, and the pure helpers (`isAppLocale`, `getDirection`, `getLocaleHref`, `getLocalizedPathname`, `getPreferredLocale`, `readCookieLocale`, `negotiateLocale`). `src/middleware.ts` imports **only** from here — importing them through `@/lib/i18n` pulled i18next, react-i18next and all four translation JSONs (~120 KB) into the edge bundle for helpers that need none of it
- **i18next config:** `src/lib/i18n.ts` — the bundled JSON resources (no backend/lazy-loading), `createI18nInstance()`, `getLocaleMessages()`, the default instance, and a re-export of everything in `locales.ts` so `@/lib/i18n` stays the single import site for the React tree
- **Routing:** locales are URL segments (`/en`, `/he`, `/ru`, `/et`). `src/middleware.ts` (it must sit under `src/` — with a `src/` directory present, `next dev --turbopack` silently ignores a project-root `middleware.ts`) redirects a locale-less path (307, path and query preserved) to `cookie ?? negotiateLocale(Accept-Language) ?? DEFAULT_LOCALE` and sets the cookie on that redirect. On a localized path it sets the cookie **only when the incoming cookie disagrees with the path locale** (the path wins) — a `Set-Cookie` on every HTML response is what stops a CDN from caching the prerendered page. The cookie is `SameSite=lax`, `Path=/`, one year, and `Secure` over https. There is **no `x-locale` request header**: injecting one made the root layout read `headers()`, which forced every route dynamic
- **Root layout:** `src/app/[locale]/layout.tsx` **is the root layout** — it owns `<html lang dir>`, the fonts, `globals.css`, the background divs, `<JsonLd locale>` and `<I18nProvider>`, all derived from the `locale` route param. There is no `src/app/layout.tsx` and no `src/app/page.tsx` (the middleware already redirects `/`). It validates the segment (404 on unknown), `generateStaticParams` from `LOCALES` (leave `dynamicParams` at its default — `false` 404s on a cache miss instead of falling back to SSR), and builds per-locale metadata: canonical URL, hreflang alternates, and the `OG_LOCALES` Open Graph map (`Record<AppLocale, string>` so a missing entry fails typecheck). Keeping this layout free of `headers()`, `cookies()` and `useSearchParams()` is what keeps `● /en /he /ru /et` prerendered
- **Provider:** `src/components/I18nProvider.tsx` — creates one stable i18n instance; language changes go through `i18n.changeLanguage` (never a route remount, which would cut the cipher animation short). Syncs `<html lang/dir>` and the locale cookie
- **Selector:** `src/components/LanguageSelector.tsx` — dropdown (not a toggle) driven by its `LANGUAGES` array (code, label, initials, flag icon). Item hrefs are the localized pathname only — the site has no query-string routes, and reading one would mean `useSearchParams`, which now **would** need a Suspense boundary around the component: the locale routes are statically rendered. A query/hash present on the client is re-attached from `window.location` on selection. Selecting a language flips `lang`/`dir` synchronously, calls `changeLanguage`, and updates the URL via `history.replaceState` (no navigation); pins the viewport during reflow (`behavior: 'instant'`, since `'auto'` would defer to the page's `scroll-behavior: smooth`), returns focus to the trigger, and announces the new language in a `role="status"` live region. ArrowDown/ArrowUp/Home/End move between items; Escape closes and so does focus leaving the container (`focusout` with a `relatedTarget` outside it), and opening from the keyboard focuses the current language. `aria-controls` is only set while the menu it names is rendered. The trigger has no `aria-label` — its accessible name includes its visible text ("Select language: EN", WCAG 2.5.3). The viewport pin itself lives in `src/lib/viewport-pin.ts` and must be called *before* the language mutation, since it samples its anchor synchronously and the `lang` flip alone reflows the page. The pin holds the reader's anchor still; the size change itself is smoothed by `CipherText`'s block-mode height ease (`src/lib/height-ease.ts`), so a translation that wraps to a different number of lines slides the content below it over 300ms instead of stepping in one frame (measured: the 1280px hero `<h1>` 240 -> 180px on en->he)
- **Fallback pages:**
  - `src/app/global-not-found.tsx` (enabled by `experimental.globalNotFound` in `next.config.ts`) — a **server** component for paths that match no route, so there is no `locale` param. It reads the locale cookie via `cookies()`, renders its own `<html lang dir>` with the font variables and `globals.css`, and emits a localized `<title>` from `getLocaleMessages(locale)`. The middleware refreshes that cookie on the very request that 404s, so `/he/foo` comes back in Hebrew and RTL. It replaces the old `not-found.tsx`, which rendered inside Next's `__next_error__` shell, had no `<title>`, and could only correct `lang`/`dir` from an effect after mount
  - `src/app/[locale]/error.tsx` — a client boundary **inside** the locale segment, so `I18nProvider` is above it and it uses `useTranslation()` rather than reading a cookie
- **Translations:** `public/locales/{en,he,ru,et}/translation.json`
- **Test fixtures:** `__tests__/fixtures/translations/{lng}.json` — fictional, edge-case-heavy content registered in `__tests__/setup.ts` via `addResourceBundle(..., overwrite=true)` so production résumé edits never break tests. Tests assert against fixture text, not production text

## Translation Key Convention

Nested, descriptive keys matching section structure:

```
section.subkey     → "about.heading", "experience.ariaLabel"
section.items[]    → "experience.jobs" (array of objects, joined to src/data/* by id/index)
ui.action          → "language.selectLabel"
meta.*             → page metadata; notFound.* / error.* → fallback pages
```

## Content Separation

Translatable text lives in the JSON files. Non-translatable metadata (URLs, technology tags, icons, repo links) lives in `src/data/experience.ts` and `src/data/projects.ts`, joined to the translated arrays by index/id in the section components.

## Patterns

```tsx
const { t } = useTranslation();
<p>{t('about.p1')}</p>                                        // simple text
const jobs = t('experience.jobs', { returnObjects: true });   // arrays of objects
<section aria-label={t('experience.ariaLabel')}>              // a11y labels
```

## RTL

`he` is the only RTL locale (`RTL_LOCALES` in `src/lib/locales.ts`). Use logical properties/utilities: `ps-*`, `ms-*`, `border-s`, `text-start`, `rtl:rotate-180`.

## Adding a New Language (checklist, mirrors how `et` was added)

1. `public/locales/{code}/translation.json` — translate from `en` (keep keys/structure identical, including `meta`, `notFound`, `error`)
2. `__tests__/fixtures/translations/{code}.json` — translate the *fixture* content (mirror the `en` fixture's keys; it has no `meta`/`notFound`/`error`)
3. `src/lib/locales.ts` — add to `LOCALES`; add to `RTL_LOCALES` if RTL. `src/lib/i18n.ts` — import the JSON and add it to `localeResources`
4. `src/components/icons/index.tsx` — add a `<Country>FlagIcon` (36×24 viewBox, `aria-hidden`)
5. `src/components/LanguageSelector.tsx` — add to `LANGUAGES` (code, native-language label, initials, flag)
6. `src/app/[locale]/layout.tsx` — add the `OG_LOCALES` entry (typecheck forces this)
7. `__tests__/setup.ts` — import the fixture and `addResourceBundle` it
8. Update tests that enumerate locales:
   - `__tests__/lib/locales.test.ts` (`LOCALES`, direction, negotiation) and `__tests__/lib/i18n.test.ts` (resource bundles)
   - `__tests__/components/I18nProvider.test.tsx` (lang/dir)
   - `__tests__/components/LanguageSelector.test.tsx` (link count + href)
   - `__tests__/components/i18n-integration.test.tsx` (new language block + selector flow, asserting fixture text)
   - `__tests__/components/icons.test.tsx` (flag icon)
   - `__tests__/app/layout.test.tsx` (static params + OG metadata + hreflang alternates)
   - `__tests__/app/sitemap.test.ts` (URL list)
9. README — language mentions and the `/en`, `/he`, … URL list
